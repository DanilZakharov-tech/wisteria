# WISTERIA · игровой прототип 0.1

Исходный код реальной React Three Fiber игры с локальным сохранением. Это ранний прототип, **не готовый сезон или публичный релиз**. Проверены TypeScript, production-сборка, правила наград, восстановление сохранения и структура GLB/PWA. Отрисовка, сенсорное управление и установка на настоящем iPhone пока не проверены.

## Запуск

Требуется Node.js 22.12+ (проверено на 24.22.1).

```bash
npm ci
npm run dev
```

Открой адрес, который напечатает Vite. WASD / стрелки или виртуальный джойстик перемещают Алину. Перетаскивание сцены поворачивает камеру, колёсико или жест двумя пальцами меняет дистанцию.

```bash
npm run build
npm test
node scripts/check-assets.mjs
```

`dist/` — готовый статический production-клиент. Для полноценного офлайна используй именно production-сборку: команда build генерирует список всех файлов для предварительного кэширования.

## Как пройти игровой цикл

1. Алина начинает на дорожке перед фонтаном. Виктория стоит немного впереди и справа.
2. Подойди на расстояние менее 2,2 игровых единиц. Нажми «Поговорить».
3. Выбери ответ: знакомство завершает первое задание, выдаёт 50 XP и 20 монет, открывает реальные задания.
4. В «Миссиях» выбери «Дом начинается с мелочей», выполни действие в жизни и подтверди. Подписчики для сюжета не нужны.
5. За выполнение начисляются награды. Повторное начисление защищено в движке.
6. У калитки дома Алины (слева от фонтана, координаты -6, 0) появляется «Войти в дом». В гостиной можно посмотреть книгу рецептов, купить растение и менять цвета платья через гардероб.
7. После задания по дому открывается задание ужина. Его завершение открывает цепочки следующей главы.
8. Закрой и открой страницу: XP, задания, одежда, знакомства, декор и аналитика восстановятся из localStorage.

Задания в реальной жизни подтверждаются игроком. Игра не утверждает, что проверила факт уборки, готовки или публикации.

## Что реализовано

- Настоящая трёхмерная улица, дома, фонтан, деревья и глициния; отдельная сцена интерьера.
- Управляемая объёмная Алина, сенсорный джойстик, клавиатура, OrbitControls, пространственные условия взаимодействия.
- Пять оригинальных GLB, каждый ~42 KB: Алина и четыре соседки. Модели простые, с восьмикостным скелетом. Семь клипов: idle, walk, joy, surprise, talk, sit, interact. В игре подключены idle/walk/joy/talk/sit; surprise и interact пока только подготовлены в файлах.
- Замена модели отделена от управления в `RiggedAvatar`. Для совместимости нового GLB сохрани имена клипов и материал `Dress`, либо настрой адаптер.
- Знакомства, варианты ответа, первая цепочка заданий, XP, монеты, 100 уровней, коллекция достижений.
- 120 конфигураций заданий: пять начальных и 115 повторяемых небольших действий. Это **не 120 уникальных сюжетных сцен**. Небольшие задания открываются тремя параллельными цепочками; интерфейс рекомендует три.
- Гардероб из четырёх цветовых вариантов, покупка растения, реальный рецепт брускетт.
- Ручной ввод Instagram-метрик. Следующий эксперимент рекомендует лучший формат/тему по доле подписок с публикации. Это простая описательная эвристика; причинность или рост не гарантируются.
- 30-дневный календарь, целевой показатель 5 000 подписчиков, добровольные задания, отсутствие штрафов за паузы.
- Zustand persist, экспорт локальной копии, опциональные Supabase Auth и загрузка/восстановление облачной копии по запросу.
- `/admin`: редактор конфигурации заданий. Доступ требует JWT `app_metadata.role=admin`; изменения защищены RLS. Клиент загружает опубликованный каталог при старте.
- Manifest, PNG-иконки, standalone, service worker, production precache всех JS/CSS/GLB. Низкое/среднее/высокое качество меняет DPR и тени.

## Структура

```text
src/
  main.tsx              интерфейс, диалоги, панели игры
  World.tsx             R3F-сцена, модели, управление и камера
  game.ts               задания, прогресс, награды, Zustand
  cloud.tsx             Supabase Auth, копии сохранений, администратор
  game.test.ts          правила наград и сюжетные зависимости
  persistence.test.ts   запись и восстановление localStorage
  style.css             адаптивный интерфейс + Tailwind
public/
  models/*.glb          собственные временные скелетные модели
  manifest.webmanifest
  sw.js                 шаблон service worker
scripts/
  avatar.mjs            воспроизводимая генерация оригинальных GLB
  offline.mjs           versioned precache production-сборки
  check-assets.mjs      проверка GLB и PWA-ресурсов

.env.example
vercel.json
```

## Supabase

1. Создай бесплатный проект Supabase. Выполни `supabase/schema.sql` в SQL Editor.
2. Скопируй `.env.example` в `.env.local`. Укажи URL и **публичный anon/publishable ключ**; service_role в клиент никогда не добавляй.
3. В Auth → URL Configuration добавь production-origin и localhost в разрешённые redirect URL. Включи email authentication.
4. Пересобери клиент. В настройках отправь себе magic link, открой письмо и войди.
5. «Сохранить в облако» загружает текущую локальную копию. «Восстановить из облака» заменяет локальную копию выбранного аккаунта. Перед восстановлением скачай экспорт.
6. Конкурентная запись защищена проверкой revision, автоматического слияния разных устройств пока нет. Офлайн сохраняется локально; загрузка в облако выполняется явно. Не привязывай одно локальное сохранение к чужому аккаунту.
7. Для администратора серверным Admin API Supabase задай `app_metadata.role=admin` выбранному пользователю. Не используй user_metadata для прав. Открой `/admin` после входа.
8. Редактор работает с полным JSON-каталогом. Не удаляй `hello`, `unpack`, `style`, `reel`, `dinner`: первая глава на них ссылается. Сохраняй уникальные ID и существующие prerequisites. Удаление/изменение старых ID требует миграции прогресса.

RLS разрешает читать и менять только собственное сохранение; менять каталог может только admin. Метрики в личной игре — самоотчёт. Экономика не предназначена для соревновательных рейтингов. Интеграционная проверка на живом Supabase **не выполнена**: проект и ключи не предоставлены.

## Instagram / Meta

Базовая игра полностью работает с ручной аналитикой. Автоматический OAuth и обновление метрик **не реализованы**. Для production-интеграции нужны Meta App, подходящий профессиональный Instagram-аккаунт, актуальные разрешения и при необходимости App Review. Секрет приложения, обмен authorization code и токены должны находиться только на сервере; токены требуется шифровать, обновлять и отзывать. Пароль Instagram не запрашивается, парсинга и обхода авторизации нет.

## iPhone и публикация

Для Vercel: создай GitHub-репозиторий с этим каталогом, импортируй его в Vercel, выбери Vite (build `npm run build`, output `dist`). Конфигурация уже находится в `vercel.json`. При подключении Supabase добавь две публичные переменные в Vercel Environment Variables. HTTPS выдаётся хостингом.

На iPhone: **Safari → Поделиться → На экран «Домой» → Добавить**. Дождись первой загрузки ресурсов онлайн. Приложение должно открываться в standalone. iOS может очистить веб-хранилище при нехватке места или ручном удалении данных: используй экспорт и облачные копии.

Деплой не выполнен: репозиторий GitHub и Vercel-проект/учётные данные не предоставлены. Подготовлены исходники и production-dist.

## Проверки и ограничения

- Production TypeScript/Vite build — выполнен; предупреждение о размере основного JS (~1,5 MB до gzip) остаётся.
- 6 автоматизированных тестов: запрет повторной награды, зависимости заданий, глава без Instagram, целостность каталога, ограничение уровней, сохранение и восстановление — прошли.
- GLB: заголовок, 8 суставов, 7 клипов; PWA: существование иконок и включение моделей/JS в precache — проверено скриптом.
- Браузерный QA **не выполнен**: `sites-preview start` завершился `listen EPERM 127.0.0.1:4173`, инфраструктура предпросмотра недоступна. Скриншоты и интерактивный проход не получены.
- Реальный iPhone, Safari, офлайн после закрытия, установка с домашнего экрана и 30 FPS **ещё требуют проверки**. По критериям задания прототип нельзя считать полностью проверенным до этого.
